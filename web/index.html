YouTube — One-Time Setup

Google requires every app to register its own OAuth client before anyone can "Sign in with Google" through it — there's no way around this step, and Slopdaddy can't do it on your behalf (a shared key baked into a public app would mean everyone who uses it fights over the same tiny daily quota). It's four clicks, about 3 minutes total. Each step below opens the exact right page — you don't need to find anything yourself.

  1. Create a Google Cloud project (any name).
  2. With that project selected, enable the YouTube Data API.
  3. Set up the consent screen: choose External, fill in just the required app name/email fields, and on "Test users" add your own Google account's email.
  4. Create the credentials: Create Credentials → OAuth client ID → Desktop app (application type matters — picking "Web application" instead will cause a redirect_uri_mismatch error when you sign in). A popup shows your Client ID and Client Secret — copy both into the fields below.

If sign-in still fails with redirect_uri_mismatch after picking Desktop app: open your client in the Credentials page and confirm its type says "Desktop app", not "Web application" — if it's the latter, add http://127.0.0.1:8123/youtube-oauth-callback under "Authorized redirect URIs" there, or just delete it and recreate it as Desktop app instead.

You can register more than one Google Cloud project (repeat the steps above) and connect the same channel under each — uploads then automatically spread across whichever project still has quota left today, instead of one project's ~6/day limit capping the whole app.
